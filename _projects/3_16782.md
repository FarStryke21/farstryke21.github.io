Multi-agent path finding is NP-hard: route a team of agents from their starts to
their goals without collisions, minimising makespan or total path length. The
one-shot version assumes every agent has a single destination and the problem
ends when everyone arrives.

<div class="figure">
    <img src="/images/projects/16782/mapf.png" alt="">
    <div class="figure__caption">The one-shot formulation: fixed starts, fixed goals.</div>
</div>

Warehouses do not work that way. An agent that reaches its goal is immediately
given another, so the problem never terminates and the plan is never finished —
the *lifelong* variant. We built a solver for it and evaluated on maps from the
League of Robot Runners, an Amazon Robotics competition on exactly this
coordination problem.

<div class="figure">
    <img src="/images/projects/16782/conflicts.png" alt="">
    <div class="figure__caption">Conflict types the planner has to resolve.</div>
</div>

## Approach

Conflict-based search splits planning across two levels. Each agent is routed
independently with A\* or Dijkstra, ignoring the others; the resulting paths are
checked for conflicts; and where two agents collide, the search branches into
child nodes that forbid one agent from that cell at that time. Each branch is
replanned and pushed back onto the open list by cost. The cheapest conflict-free
node wins.

Making that lifelong meant deciding when to re-plan. Replanning every timestep
is wasteful — most steps change nothing. Our version keeps a per-agent flag and
only re-runs the search when an agent actually reaches its goal and receives a
new one, since that is the only event that invalidates the current solution.

| Map | Agents | Tasks completed | Solve time |
|---|---|---|---|
| 32 × 32 | 20 | 3416 | 70.8 s |
| 33 × 57 | 25 | 3666 | 72.7 s |

The larger map completed more tasks for almost the same solve time — a 7 %
increase in throughput for 3 % more computation. The extra agents did most of
that work; the larger search space and higher CBS call count absorbed the rest.
Two configurations is not enough to claim the trend holds, but it does suggest
the replanning trigger is keeping the cost of "lifelong" closer to the cost of
one-shot than a naive every-timestep solver would.
